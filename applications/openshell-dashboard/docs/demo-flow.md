# OpenShell + openclaw demo flow — CoCo spoke, aipcc

Reusable demo script. Every beat has the action, the exact commands/prompts,
and the expected evidence. Technical setup details live in
[provider-setup-openclaw.md](provider-setup-openclaw.md).
**Demo-phase follow-up**: task 8 (gateway TLS + Route) — after enabling it,
update this script: the port-forward prerequisite disappears and the exposed
service URLs go through the cluster ingress
(`https://default--openclaw--openclaw-dashboard.openshell.<route-host>/`).

## Prerequisites

- Hub + coco spoke up: kubeconfigs `~/.kube/config.sno-test` (hub),
  `~/.kube/config.coco1` (spoke)
- Port-forward running: `oc port-forward svc/openshell -n openshell 8080:8080`
  (spoke kubeconfig)
- CLI registered + logged in (`openshell gateway login openshell`)
- `openclaw` sandbox **Ready** (created via CLI with `--policy` +
  digest-pinned image `quay.io/eformat/openshell-openclaw@sha256:201dd68e…`)
- MaaS provider attached (`openshell sandbox provider status openclaw openai` →
  `ready`, enforce mode)
- Dashboard: `https://openshell-dashboard.apps.<spoke-domain>` (Keycloak →
  oauth2-proxy — real RBAC, no unauthenticated access)

## Beat 1 — The platform: OpenShell dashboard on the CoCo spoke

**Show**: the dashboard at `https://openshell-dashboard.apps.<domain>` — login
through Keycloak. The sandbox list shows `openclaw` **READY**.

**Say**: every sandbox is a Confidential Container VM; access is RBAC from the
start — no `allow_unauthenticated_users`, the dashboard path is Keycloak →
oauth2-proxy → BFF.

**Check**:
```bash
export KUBECONFIG=~/.kube/config.coco1
oc get sandboxes.agents.x-k8s.io -n openshell   # default--openclaw
```

## Beat 2 — The governance surface: policy

**Show**: the sandbox's **Policy** tab — github (L4 + rest) and MaaS egress,
default-deny for everything else.

**Say**: the policy is authored YAML (deny_unknown_fields, snake_case) —
`network_policies` with per-binary rules; the dashboard display is a view of
it. MaaS egress is delegated to the attached provider profile
(`applications/openshell-dashboard/provider-profiles/openai.yaml`): **enforce**,
node binaries only.

**Check** (the effective policy + the provider profile):
```bash
openshell policy get openclaw -g openshell
openshell sandbox exec openclaw -- cat /etc/openshell/policy.yaml | head -30
```

## Beat 3 — The credential story: providers

**Show**: the **Providers** tab — `openai` attached, no secret in sight.

**Say**: the agent never sees the real credential. At startup OpenShell
replaces it with an opaque placeholder (`openshell://resolve/…`) in the
agent's environment; the proxy resolves recognized placeholders in
`Authorization: Bearer <placeholder>` immediately before forwarding — the real
key is injected workspace-side on the way out.

**Check**:
```bash
openshell sandbox exec openclaw -- env | grep OPENAI_API_KEY
# → OPENAI_API_KEY=openshell://resolve/…   (never the real key)
```

## Beat 4 — The agent works: clone + advice (web console)

**Show**: the Control UI (chat/main) — model selector **GLM 5.3 Flash**.

**Prompt 1** (paste into the console):
```
Clone https://github.com/octocat/Hello-World into /sandbox/.openclaw/workspace/hello-world, then list the files.
```

**The moment**: the agent hits `SSL verification (self-signed cert in chain)`,
**diagnoses it** ("likely a sandbox proxy"), auto-fixes with
`http.sslVerify=false`, and completes — then tells you why. The proxy
terminates all transparent TLS (how L7 inspection works) and re-signs with its
own CA; the guest can't validate it. Self-correction, on stage.

**Result**: `Done, Mike. Cloned into /sandbox/.openclaw/workspace/hello-world.
Contents: .git/ README`

**Prompt 2**:
```
Read the README file in the hello-world repo and give me two concrete improvements as coding advice.
```

**Result**: two concrete suggestions, generated by glm-5.3-flash through the
MaaS provider.

## Beat 5 — The evidence: enforced, least-privilege egress

**Say**: every egress decision is recorded — here's the trail for what you
just watched.

**Check**:
```bash
openshell logs openclaw 2>&1 | grep -iE "github\.com|maas\.apps" | tail -8
```
```
NET:OPEN  ALLOWED /usr/bin/git(...)    -> github.com:443               [policy:github engine:opa]
NET:OPEN  ALLOWED /usr/bin/node-26(0)  -> maas.apps...:443             [policy:_provider_openai engine:opa]
HTTP:POST ALLOWED POST .../v1/chat/completions                         [policy:_provider_openai engine:l7]
```

**Say**: git went L4-only (github.com is `protocol: tcp` — git's binary POST
is exactly what rest L7 inspection would deny), the model calls are L7-inspected
and **enforced**. Nothing else leaves the VM.

**Check** (nothing new proposed — everything was policy-allowed):
```bash
openshell rule get openclaw -g openshell --status pending
# → No network rules
```

## Beat 6 — The governance loop: proposals

**Show**: the **Proposals** tab — the advisor proposes rules for blocked
requests with confidence scores; the human decides.

**Say**: during bring-up the agent triggered 5 proposals. All 5 were denied
with reasons — the audit trail records each:

| Proposal | Decision | Reason |
|---|---|---|
| `allow_example_com_443` | denied | default-deny — no workload needs it |
| `allow_telemetry_openclaw_ai_443` | denied | telemetry egress |
| `allow_clawhub_ai_443` | denied | unused service |
| `allow_openrouter_ai_443` | denied | models-scan artifact |
| `allow_api_github_com_443` | denied | redundant — authored policy already allows it |

**Check**:
```bash
openshell rule get openclaw -g openshell --status pending   # empty
openshell logs openclaw 2>&1 | grep -E "DENIED" | tail -4
# → NET:OPEN [MED] DENIED /usr/bin/node-26(0) -> telemetry.openclaw.ai:443 [reason:transparent_tcp_policy_denied]
```

## Beat 7 — Operator access: the CLI

**Show**: from the laptop, through gateway RBAC:
```bash
openshell sandbox exec openclaw -- uname -a     # non-interactive exec
openshell sandbox connect openclaw              # attach to the main process (Ctrl-P Ctrl-Q to detach)
```

**Say**: operator access is the same gateway, the same RBAC, the same audit.
